# 松山YEG 夜の飲食店MAP

松山YEG会員が経営する夜の飲食店を、地図と一覧から探せる飲み歩きマップです。

- 地図上のピンをタップ → その店の説明まで一覧が自動でスクロール（吹き出しにも店舗画像）
- 「マップアプリで開く」→ スマホのGoogleマップアプリが起動（道案内へつながります）
- 一覧のカードをタップ → 地図がその店に移動してピンが開く
- 店舗画像をタップ → 大きく表示
- ジャンル・エリア・キーワードで絞り込み（PC・タブレットではジャンルは色付きボタン、エリアはスイッチ。スマホではどちらもプルダウン）
- お店のピン・一覧の丸付き番号・ジャンルボタンは、ジャンルごとに同じ色
- 会場などの「目印」をブランドカラーのピンで常に表示（`js/landmarks.js`）。地図の表示範囲の計算には含めない
- スマホ / PC 両対応
  - スマホ：地図を全画面に表示し、一覧はGoogleマップのように下から引き出すシート（最小／少しだけ／半分／全開の4段階。上部のつまみ、または一覧をスワイプ）
  - PC：左に一覧、右に地図

地図には Leaflet + OpenStreetMap を使用しています。**APIキーや課金設定は不要**です。

## 全体の構成

```
[閲覧者のスマホ・PC]
      │ ① サイトを開く
      ▼
[GitHub Pages]     … フロント（index.html / css / js）
      │ ② 店舗データを取りに行く
      ▼
[GAS]              … バックエンド（gas/Code.gs）。公開してよい項目だけをJSONで返す
      │ ③ 読む
      ▼
[スプレッドシート]  … DB。一般公開しない
   ├ フォームの回答 1 … 生の回答。運営は触らない
   └ MAP掲載         … サイト用。回答を取り込み、運営が表記を整える（サイトが読むのはこちらだけ）
```

## 1. ローカルで見る

ファイルを直接ダブルクリックして開くと、ブラウザの制限で店舗データを読み込めません。
かならず簡易サーバー経由で開いてください。

```bash
python -m http.server 5500
```

起動したら、ブラウザで <http://localhost:5500> を開きます。

Node.js を使う場合は次でも構いません。

```bash
npx serve -l 5500 .
```

> ローカルで開いた場合も、店舗データは本番と同じGASから読み込みます。

### サーバーの止め方

- コマンドを打ったターミナルで起動した場合 → そのターミナルで `Ctrl + C`
- VSCodeの「実行とデバッグ」(`.claude/launch.json` の `yeg-map` 設定)から起動した場合 → `Ctrl+C` は効かないので、「実行とデバッグ」パネルの■(停止)ボタンを押す
- どちらか分からない/確実に止めたい場合 → ポート番号（例: 5500）を使っているプロセスを調べて終了する

```powershell
# ポート5500を使っているプロセスのPIDを確認
Get-NetTCPConnection -LocalPort 5500 | Select-Object OwningProcess

# そのPIDを終了（例: 1234）
Stop-Process -Id 1234
```

## 2. GASの準備（最初の1回だけ）

### ① スクリプトを貼り付ける

1. フォームの回答スプレッドシートを開く
2. メニューの「拡張機能」→「Apps Script」
3. 最初から入っているコードをすべて消し、`gas/Code.gs` の中身を貼り付けて保存（`Ctrl + S`）
4. スプレッドシートのタブに戻って再読み込みすると、メニューに「**MAP管理**」が出ます

### ② MAP掲載シートを作る

「MAP管理」→「**① MAP掲載シートを準備**」を実行します。

- 初回は「承認が必要です」と出るので、自分のアカウントを選んで許可します
- 「このアプリはGoogleで確認されていません」と出た場合は、「詳細」→「（プロジェクト名）に移動」で進めます（自分で作ったスクリプトなので問題ありません）

「MAP掲載」シートが作られます。列は見出しの名前で探しているので、後から並べ替えても動きます。

| 列 | 内容 |
| --- | --- |
| 氏名 | 店舗の代表者。サイトに「代表者」として表示されます |
| 店舗名・住所・連絡先 | フォームの回答から取り込み。表記は自由に整えてOK |
| 営業時間 | `hh:mm-hh:mm`（24時間表記）。取り込み時に自動変換されます（下記） |
| 店舗ロゴ | フォームでアップロードされた画像のURL |
| 収容人数 | 数字だけなら、サイトでは「最大◯名」と表示されます |
| 掲載（補助列） | チェックを入れたお店だけがMAPに出ます |
| 業態（補助列） | サイトのジャンル絞り込みに使います |
| エリア（補助列） | 運営が手で入力します（例：中心地）。入力した値がサイトのエリア絞り込みになります。空欄のお店は「すべてのエリア」でだけ表示されます |
| 緯度・経度（補助列） | 住所から自動入力。ずれていたら手で直せます |
| 確認メモ（補助列） | 自動変換や位置の取得で気になる点があると、メモが入ります。確認したら消してOK |
| 回答日時（補助列） | 取り込み元の回答の日時 |

### ③ ウェブアプリとして公開する

1. Apps Scriptの画面右上の「デプロイ」→「新しいデプロイ」
2. 種類の選択（歯車アイコン）で「**ウェブアプリ**」
3. 次のとおり設定して「デプロイ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 表示された「ウェブアプリのURL」（`…/exec` で終わるもの）をコピー

### ④ フロントにURLを設定する

`js/data-source.js` の冒頭に貼り付けます。

```js
const SOURCE = {
  gasUrl: 'https://script.google.com/macros/s/xxxxxxxx/exec'   // ← ここに貼る
};
```

## 3. 日々の運用（お店の追加・修正）

1. 会員さんがGoogleフォームに回答する
2. 「MAP管理」→「**② 新しい回答を取り込む**」
   - まだ取り込んでいない回答だけが、「MAP掲載」シートに追加されます（「掲載」は未チェック）
   - メールアドレスは取り込みません
   - 数字・記号は半角にそろえ、営業時間を `hh:mm-hh:mm` に変換し、住所から位置を入力します（エリアは手で入力）
3. 「確認メモ」を見ながら表記を整え、「**掲載**」にチェックを入れる
4. 「MAP管理」→「**③ MAPに反映（公開）**」
   - 掲載するお店の店舗ロゴを、表示できるよう公開設定に変更します
   - サイト用の公開データを作り直します
5. サイトを再読み込みすると反映されます

**シートを直しただけではサイトは変わりません。必ず「③ MAPに反映」を押してください。**
（公開データを作っておくことで、サイトの表示を速くしています）

「MAP管理」→「**MAPに公開される内容を確認**」で、サイトに出るお店と項目を事前に確認できます。

### 営業時間の自動変換

| フォームの記入 | 変換後 |
| --- | --- |
| 17時～0時 | 17:00-00:00 |
| 21:00〜翌3:00 | 21:00-03:00 |
| 18:00〜25:00 (LO：24:00) | 18:00-01:00 |
| 9：30〜20：00 | 09:30-20:00 |
| 17時半〜24時 | 17:30-00:00 |

- 日をまたぐ時間は `00:00`〜`23:59` で表します（25:00 → 01:00）
- 変換したときは、元の記入を「確認メモ」に残します。「LO」などの補足は変換で省かれるので、必要ならメモを見て書き足してください
- 開始と終了が読み取れない記入（「昼から夜まで」など）は、そのまま残して「確認メモ」でお知らせします

### 知っておくと便利なこと

- **掲載をやめる**：「掲載」のチェックを外して「③ MAPに反映」（データは消えません）
- **同じお店がフォームに回答し直した場合**：運営が整えた内容を上書きしないよう、新しい行は作りません。そのお店の「確認メモ」に「フォームに新しい回答あり（日時）」と書かれるので、回答シートと見比べて手で反映してください
- **住所を直したとき**：その行を選択して「MAP管理」→「**選択した行の位置を住所から取り直す**」
- **お店を手で追加したいとき**：MAP掲載シートの一番下の行に直接書き込み、「③ MAPに反映」を押すと、位置と「掲載」のチェックボックスが自動で入ります（チェックボックスは、お店が入っている行にだけ付きます）
- **緯度・経度を手で調べるとき**：Googleマップでお店の位置を右クリック（スマホは長押し）→ 一番上の `33.8408, 132.7663` のような数値をクリックするとコピーされます。前が緯度、後ろが経度です
- **最初から取り込み直したいとき**：Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」にある `lastImportedAt` を削除すると、次の取り込みで全回答が対象になります（すでにMAP掲載にあるお店は、上と同じくメモだけになります）

## 4. 安全性について

- 「MAP掲載」シートには、メールアドレスが最初から入りません
- GASが外部に返すのは、店舗名・代表者（氏名）・業態・エリア・住所・連絡先・営業時間・収容人数・店舗ロゴ・位置だけです（`gas/Code.gs` の `toPublicShop`）
- **氏名は代表者としてサイトに公開されます。** フォームの案内文などで、会員さんに伝えておいてください
- スプレッドシートの共有設定は「**制限付き**」のままにしてください（一般公開は不要です）
- GASを修正したときは、「デプロイ」→「**デプロイを管理**」→ 既存のデプロイを編集 →「新バージョン」で更新してください。「新しいデプロイ」を作るとURLが変わり、古いURLも動き続けます
- GASのURL（`js/data-source.js`）は公開されていても問題ありません。URLから動くのは公開データを返す `doGet` だけです
- **店舗の実データをこのフォルダ（GitHub）に置かないでください**。公開リポジトリは誰でも中身を見られます

## 6. 目印（会場など）

`js/landmarks.js` に書いた場所が、ブランドカラーの「★」ピンで地図に常に表示されます。一覧の上には、その場所へ移動するボタンも並びます。

```js
const LANDMARKS = [
  {
    label:   '懇親会場',                       // ピンとボタンに出る短い名前
    name:    'ANAクラウンプラザ 松山',          // 施設名
    address: '愛媛県松山市一番町3丁目2-1',      // 「マップアプリで開く」の検索にも使う
    lat: 33.840889,                            // 緯度
    lng: 132.768555                            // 経度
  },
  // …
];
```

- **イベントが終わったら**：中身を空（`const LANDMARKS = [];`）にしてプッシュすると、ピンとボタンが消えます
- **次のイベントで使うとき**：中身を書き換えてプッシュするだけです
- 引いた地図では、名前を隠した「★」だけの小さなピンになります（ズーム15未満）。寄ると名前が出ます

---

### ジャンルの色

PC・タブレットのジャンルボタンの色は `js/genre-colors.js` で決めています。

```js
const GENRE_COLORS = {
  '居酒屋':   '#c2410c',
  'ラウンジ': '#7c3aed',
  // …
};
```

- ジャンル名は、スプレッドシートの「業態」列と同じ表記で書きます
- 書いていないジャンルにも自動で色が付きます（同じ名前なら常に同じ色）。決めたい色があるジャンルだけ書き足してください
- 選んだボタンは白い文字になるので、濃いめの色にしてください

### スマホでの表示

画面幅600px未満（スマホ）では、一覧のシートを広く使うため、次のように表示が変わります。

- 検索欄は、地図の上部に重ねて表示します（入力を始めるとシートが全開になります）
- 絞り込みは、ジャンルとエリアのプルダウンを横に並べるだけにします（見出しなし）
- 目印の行は表示しません。目印のピンは地図上に表示されます

スマホ・タブレット（画面幅900px未満）では、「全体表示に戻す」ボタンはシート上部の件数の横にあります。
シートは4段階で、操作に合わせて自動で高さが変わります。

| 段階 | 高さ | なるとき |
| --- | --- | --- |
| 最小 | つまみ・件数・「全体表示に戻す」が見えるギリギリ | ピンをタップしたとき（地図と吹き出しを広く見せる） |
| 少しだけ | 絞り込み（プルダウン）が見えるギリギリ | **スマホで最初に開いたとき**、「全体表示に戻す」を押したとき |
| 半分 | 画面の半分 | タブレットで最初に開いたとき |
| 全開 | 検索欄の下まで | 吹き出しの「詳しく見る」を押したとき、検索欄に入力するとき |

「最小」と「少しだけ」の高さは、実際のボタンやプルダウンの位置から自動で計算しています。
地図の吹き出しは、地図に重ねた部品（検索欄・シート）より手前に出せないため、それらに隠れない位置へ地図が自動でずれて開きます。

### 現在地

地図左上（拡大・縮小ボタンの下）の現在地ボタンを押すと、ブラウザの確認のあと、現在地を青い点（薄い円は誤差の範囲）で表示します。処理は `js/locate.js` です。

- 位置情報はブラウザの中だけで使い、どこにも送りません。確認はボタンを押したときだけ出します
- 地図が動くのは押した直後の1回だけです。歩いている間は青い点だけが動きます。もう一度押すと現在地へ戻ります
- 松山の中心部から20km以上離れている場合は、地図を動かさずにお知らせだけ出します（遠方から下見している人向け）
- 前に「許可しない」を選んだ人や、端末の位置情報がオフの人がボタンを押すと、許可し直す手順を表示します。手順は iPhone・Android・パソコンで出し分け、LINEなどのアプリ内ブラウザでは「ブラウザで開き直す」方法を案内します
- 確認画面でいま「許可しない」を選んだ直後は、手順までは出さず短いお知らせだけにします

## 7. ファイル構成

```
├── index.html            画面の骨組み
├── css/style.css         見た目
├── js/
│   ├── landmarks.js      目印（会場など）の一覧
│   ├── genre-colors.js   ジャンルボタンの色

│   └── app.js            地図と一覧の連動処理
├── gas/
│   └── Code.gs           GASのコード（スプレッドシートに貼り付けて使う。サイトには不要）

└── .claude/launch.json   ローカル確認用サーバーの設定
```
